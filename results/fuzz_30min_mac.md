## What clean means

A target is clean when its status line says exit 0 and crashes 0; no input was saved under its name; its raw log has libFuzzer's line `Done <N> runs in <S> second(s)`, with S at least 1,800 and N the executions its status line gives, and no `ERROR:`, `FUZZ_CHECK failed` or `SUMMARY:` line; and the run's status file ends with ALL DONE. scripts/fuzz_report.py writes no file for a run in which any target is not clean.

## What it does not show

- A count of executions is not a measure of coverage, and the targets' counts are not comparable: each input of `fuzz_book` is a stream of order messages replayed through every arm of the fast book in turn and through the reference book, the two compared in full after every message, while `fuzz_decode` decodes one message of each type an input.
- `fuzz_kernels` ran the parsing kernels this host builds. Kernels for another architecture are not built here, so this run did not fuzz them.
- Nothing here is timed. The run says only that no target failed in 1,800 s at the commit above.
