## What was run

Each process maps the day, reads every page and finds every page resident, runs one untimed
warm-up of the work pass, then four timed passes in the order walk, work, work, walk
(`bench/kernel_experiments.hpp`). The walk is the same loop with the same frame walk and type
test, the measured operation replaced by adding the type byte the walk has loaded already.
The work passes less the walk passes, over the items the operation applies to, is the
operation's cost where it sits in a real loop: an item's figure, not a message's. On a vector
kernel the whole pass, loop and kernel, is compiled inside the kernel's target region
(`itch::kernels::run`).

Counted on this host, over each whole timed pass: cycles, instructions, branch misses, `cache-misses`, L2 misses, `r0843:u`, floor on DRAM demand fills.

## What this does not show

- **Pinned, not isolated.** Core 4 under the performance governor, its SMT sibling idle by the
  machine check, but turbo on and no core isolated, so the clock moves: cycles, not ns, are the
  figure to compare.
- **Zen 1's counters.** `cache-misses` counts L2 misses on Zen 1 (PMCx064 umask 0x09,
  `results/counters_zen1_events_debian.md`), not last-level misses, and `r0843:u` is a floor
  on DRAM demand fills. No FP-pipe event is read, so that Zen 1 runs a 256-bit operation as two
  128-bit ones comes from Agner Fog's tables and E12's listings, not from a count.
- **One day, one host.** AVX2 here and NEON on the Mac are different experiments: no figure
  here answers a Mac one.
