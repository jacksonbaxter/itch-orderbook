# itch-orderbook

A Nasdaq TotalView-ITCH 5.0 feed handler and full-depth order book in C++23, with a backtester, market maker, lock-free queue and browser demo.

- **Correct:** 0 divergences from an independent reference book in 3.08 billion messages over 10 full sessions ([results/oracle_sessions.md](results/oracle_sessions.md)); no heap allocation after warm-up.
- **Fast:** every symbol's book rebuilt at 5.15 M msg/s on one core of an AMD Ryzen Embedded V1605B (Zen 1) ([results/bench_book_paged-flat_ram_debian_12302019.md](results/bench_book_paged-flat_ram_debian_12302019.md)), and 21.87 M msg/s on an Apple M4 Max ([results/bench_book_paged-flat_ram_mac_12302019.md](results/bench_book_paged-flat_ram_mac_12302019.md)).
- **Bars:** most speed bars are other open-source books' best published figures, mostly on newer desktop CPUs; the Zen 1 host misses most. [RESULTS.md](RESULTS.md) has every result.

## What is built

- A parser for the framed feed that no wire content can abort, fuzzed under ASan and UBSan ([fuzz run](results/fuzz_30min_mac.md)).
- SIMD parse kernels for NEON, SSSE3, AVX2, AVX-512 VBMI and WebAssembly SIMD128, each tested against scalar.
- `FastBook` in four arms, a hash or paged order index with linked or flat levels, against a `std::map` book.
- An oracle that checks the book after every message against a reference book that reads the wire by itself ([docs/NOTES.md](docs/NOTES.md)).
- Trade checks against SEC MIDAS and Nasdaq CrossStats; per-symbol volume (T-TRADE-3) fails on four of the ten sessions.
- Invariants on the book; the strict never-crossed rule (T-INV-2) fails on real data ([RESULTS.md](RESULTS.md#how-to-read-them)).
- A benchmark harness for any book design, which refuses to publish a run it cannot stand behind.
- An event-driven backtester with a queue model; on the Zen 1 host its shadow-order replay (T-BT-3) is missed.
- An Avellaneda-Stoikov market maker with PnL attribution; its replication of the paper's tables (T-MM-2) fails.
- An SPSC ring between a parser thread and a book thread; its round trip against other queues (T-SPSC-1) is missed.
- A pool allocator for the book's nodes; its arms take page faults in a timed pass, so its fault check (T-ARENA-1) fails.
- The pool arm on explicit huge pages has not run: the Zen 1 host reserves none ([docs/NOTES.md](docs/NOTES.md)).
- A UDP replay on sockets and io_uring; lossless at Nasdaq's peak (T-URING-2) is met by S4 in 10 runs of 10 ([bisect](results/udp_bisect_debian_12302019.md)).
- A browser demo in `docs/`: the same `FastBook` in WebAssembly, replaying one symbol's day ([timing](results/wasm_replay_mac_12302019.md)).
- Fuzz targets, sanitizer builds, and a fault matrix that plants each bug in a copy of the tree to show its check catches it.

The GitHub Actions workflow in `.github/workflows/ci.yml` builds the release preset and runs every unit test on x86-64 Linux with GCC and Clang, arm64 Linux with GCC and arm64 macOS with Clang, and builds the parser and the demo's engine with Emscripten. The sanitizers, clang-tidy and the fault matrix run in `scripts/check.sh`, not in CI. [docs/NOTES.md](docs/NOTES.md) says what the first runs on GitHub found.

## Build and test

You need CMake 3.28 or newer (the minimum `CMakePresets.json` sets), Ninja, Python 3 and a C++23 compiler, taken from `CC` and `CXX`. Tested: Clang 23.1.4 on both hosts and in CI, and GCC 14 in CI on x86-64 and arm64 Linux; the demo's engine builds with Emscripten 6.0.13. <!-- figures: not measured -->

On macOS, with a Clang that is not Apple's, the build links that toolchain's own static libc++, found beside the compiler or named by `ITCH_LIBCXX_DIR` (set it to an empty value to opt out), since its headers can be newer than the system's library (`cmake/ItchOptions.cmake`).

```sh
cmake --preset release
cmake --build --preset release
ctest --preset release
```

The presets are `release`, `asan-ubsan`, `tsan`, `fuzz`, `tidy` and `wasm`. `wasm` needs `EMSDK` set. `fuzz` needs a Clang with libFuzzer.

Third-party code comes through CMake FetchContent, each pinned by SHA-256 in `cmake/ItchDependencies.cmake`, into `build/_downloads`. `ITCH_MIMALLOC`, which fetches mimalloc for the node book's mimalloc arm (T-ARENA-1), is on in the `release` and `tidy` presets and off in the others. Two more are off unless you turn them on:

```sh
cmake --preset release -DITCH_COMPARISON_QUEUES=ON       # the queues T-SPSC-1 compares against
cmake --preset release -DITCH_LIBURING_ROOT=<prefix>     # a liburing build, Linux only
```

## Fetch the data

The ITCH days and reference files are not in this repo. They go to `data/`, which is gitignored. One day, 12302019, is 3.52 GB compressed and 8.25 GB unpacked (`scripts/data_manifest.json`). <!-- figures: not measured -->

```sh
python3 scripts/fetch_data.py --day 12302019     # fetch one day and verify it
python3 scripts/fetch_data.py --ref all          # CrossStats and MIDAS
scripts/check_real_day.sh                        # the checks that need a real day
scripts/check_real_day.sh --arms all             # the same, on every arm of the fast book
```

## The headline's command

The in-memory benchmark holds the whole day in memory: its peak resident set was 9.59 GiB ([results/bench_book_paged-flat_ram_debian_12302019.md](results/bench_book_paged-flat_ram_debian_12302019.md)). That file's Commands section gives the command that made it, run under the host's measurement wrapper, which records the load before and after and is not in this repository. `<raw>` is the run's own folder, which held the release build's binaries, the day and the raw records; it is not committed ([RESULTS.md](RESULTS.md#raw-records) says why), and a rerun points `--bench`, `--probe` and `--input` at `build/release/bench/` and `data/` instead:

```sh
taskset -c 4 python3 -B scripts/bench_driver.py --bench <raw>/bench_replay --probe <raw>/bench_probe \
  --input <raw>/12302019.NASDAQ_ITCH50 --prediction P-0015 --repetitions 3 --raw-dir <raw> \
  --out 'results/bench_book_{design}_ram_debian_12302019.md' \
  --design hash-linked --design hash-flat --design paged-linked --design paged-flat \
  --design map-fresh --design map-aged --throughput-only map-fresh --throughput-only map-aged \
  --throughput-only-why 'T-DESIGN-1 needs only the throughput of the map designs, and leaving out their latency pass leaves out the one large allocation their timed processes make besides the copy of the day, so that the run fits beside the other work of the host' \
  --input-mode ram --core 4 --title 'Book design {design} on debian, 12302019, the file in memory'
```

## Run the demo

`docs/` holds a static page that replays one symbol's extract on the same `FastBook` as the native build, compiled with `em++ -O3 -msimd128` into a fixed 1 GiB memory, and animates its depth and trades. The extract and the engine are made locally into `docs/local/`, which is gitignored, so no market data is committed. The page is not deployed anywhere. <!-- figures: not measured -->

```sh
cmake --preset release && cmake --build --preset release --target itch_extract
python3 scripts/demo.py extract --day data/12302019.NASDAQ_ITCH50 --symbol AAPL
python3 scripts/demo.py build      # needs EMSDK set
python3 scripts/demo.py serve      # then open http://127.0.0.1:8000/
```

The server sends the cross-origin isolation headers, so the browser's clock is clamped to 5 µs in Chrome rather than 100 µs, and `file://` cannot load the engine. The page shows messages/sec from whole batches only and no per-message latency, and says why. <!-- figures: not measured -->

## Check everything

```sh
scripts/check.sh               # every stage, one at a time
scripts/check.sh --quick       # the stages a change should pass before a commit
scripts/check.sh --list        # the stages
scripts/check.sh --only NAME   # one stage
```

It reads nothing from `data/`. Each stage's log is in `build/check-logs/`. The demo stage opens the page in a headless browser: set `ITCH_BROWSER` to a Chrome or Chromium binary, or pass `--without-browser` to run the rest of that stage, and the summary says so.

To bisect, skip the commits that [docs/NOTES.md](docs/NOTES.md) lists under "Commits a bisect should skip": some fail their own tests or a check stage, and some do not build with GCC 14.
