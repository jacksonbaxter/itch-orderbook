# itch-orderbook

A Nasdaq TotalView-ITCH 5.0 feed handler and full-depth order book in C++23, with a backtester, market maker, lock-free queue and browser demo.

- **Correct:** 0 divergences in 3.08 billion messages over 10 full sessions, checked against a simple book sharing no code ([results/oracle_sessions.md](results/oracle_sessions.md)).
- **Speed:** every symbol's book rebuilt at 5.15 M msg/s on one core of a Zen 1 AMD Ryzen Embedded V1605B ([results/bench_book_paged-flat_ram_debian_12302019.md](results/bench_book_paged-flat_ram_debian_12302019.md)); 21.87 M msg/s on an Apple M4 Max ([results/bench_book_paged-flat_ram_mac_12302019.md](results/bench_book_paged-flat_ram_mac_12302019.md)).
- **Targets:** most speed bars are open-source projects' best figures, mostly from x86 desktops; the Zen 1 host misses most. [WRITEUP.md](WRITEUP.md) gives what was measured, not the host's share; [RESULTS.md](RESULTS.md) has every result.

## What is built

- A parser for the framed feed, designed so that no wire content can abort it, fuzzed under ASan and UBSan ([fuzz run](results/fuzz_30min_mac.md)).
- SIMD parse kernels for NEON, SSSE3, AVX2, AVX-512 VBMI and WebAssembly SIMD128, each tested against scalar.
- `FastBook`, which keeps every symbol's full-depth book, in four designs: a hash or paged order index, linked or flat levels.
- An oracle comparing what each message can change with the second book, and the whole book by hash every million messages.
- Trade checks against SEC MIDAS and Nasdaq's crosses file; per-symbol volume (T-TRADE-3) fails on four of the ten sessions.
- Invariant checks on the book; the strict never-crossed rule (T-INV-2) fails on real data ([RESULTS.md](RESULTS.md#how-to-read-them)).
- A benchmark harness that times any book design, records its host and refuses to publish a run it cannot stand behind.
- A backtester that queues simulated orders among real ones; on the Zen 1 host its shadow-order replay (T-BT-3) is missed.
- An Avellaneda-Stoikov market maker on the backtester, its PnL split into spread capture, adverse selection and inventory.
- An SPSC ring that carries messages from a parser thread to a book thread, compared with other queues on the Zen 1 host.
- A pool allocator for the book's nodes, run in three designs on base pages and on transparent huge pages.
- A UDP replay over sockets and io_uring; lossless at Nasdaq's peak (T-URING-2) is met by S4 in 10 runs of 10 ([bisect](results/udp_bisect_debian_12302019.md)).
- A browser demo in `docs/` that replays one symbol's day on the same `FastBook`, compiled to WebAssembly ([timing](results/wasm_replay_mac_12302019.md)).
- Fuzz targets, sanitizer builds, and a fault matrix that plants each bug in a copy of the tree and runs its check ([run](results/fault_matrix.md)).

## Build and test

You need CMake 3.28 or newer (the minimum `CMakePresets.json` sets), Ninja, Python 3 and a C++23 compiler, taken from `CC` and `CXX`. Tested: Clang 23.1.4 on both hosts and in CI, and GCC 14 in CI on x86-64 and arm64 Linux; the demo's engine builds with Emscripten 6.0.13. <!-- figures: not measured -->

On macOS, with a Clang that is not Apple's, the build links that toolchain's own static libc++, found beside the compiler or named by the environment variable `ITCH_LIBCXX_DIR` (set it to an empty value to opt out; CMake's `-D` does not set it), since its headers can be newer than the system's library (`cmake/ItchOptions.cmake`).

```sh
cmake --preset release
cmake --build --preset release
ctest --preset release
```

The presets are `release`, `asan-ubsan`, `tsan`, `fuzz`, `tidy` and `wasm`. `wasm` needs `EMSDK` set. `fuzz` needs a Clang with libFuzzer.

Third-party code comes through CMake FetchContent, each pinned by SHA-256 in `cmake/ItchDependencies.cmake`, into `build/_downloads`. `ITCH_MIMALLOC`, which fetches mimalloc for the node book's mimalloc arm (T-ARENA-1), is on in the `release` and `tidy` presets and off in the others. Two more are off unless you turn them on:

```sh
cmake --preset release -DITCH_COMPARISON_QUEUES=ON       # other open-source queues, timed beside the ring (T-SPSC-1)
cmake --preset release -DITCH_LIBURING_ROOT=<prefix>     # a liburing build, Linux only
```

## Fetch the data

The ITCH days and reference files are not in this repo. They go to `data/`, which is gitignored. One day, 12302019, is 3.52 GB compressed and 8.25 GB unpacked (`scripts/data_manifest.json`). <!-- figures: not measured -->

```sh
python3 scripts/fetch_data.py --day 12302019     # fetch one day and verify it
python3 scripts/fetch_data.py --ref all          # CrossStats and MIDAS
scripts/check_real_day.sh                        # the checks that need a real day
scripts/check_real_day.sh --arms all             # the same, on every arm of the fast book
```

## Rerunning the headline's book benchmark

The in-memory benchmark holds the whole day in memory: its peak resident set was 9.59 GiB ([results/bench_book_paged-flat_ram_debian_12302019.md](results/bench_book_paged-flat_ram_debian_12302019.md)). That file's Commands section gives the command that made it, run under the host's measurement wrapper, which records the load before and after and is not in this repository. `<raw>` is the run's own folder, which held the release build's binaries, the day and the raw records; it is not committed ([RESULTS.md](RESULTS.md#raw-records) says why), and a rerun points `--bench`, `--probe` and `--input` at `build/release/bench/` and `data/` instead. `--throughput-only-why` needs a reason; the published run's own is in that file's Commands section:

```sh
taskset -c 4 python3 -B scripts/bench_driver.py --bench <raw>/bench_replay --probe <raw>/bench_probe \
  --input <raw>/12302019.NASDAQ_ITCH50 --prediction P-0015 --repetitions 3 --raw-dir <raw> \
  --out 'results/bench_book_{design}_ram_debian_12302019.md' \
  --design hash-linked --design hash-flat --design paged-linked --design paged-flat \
  --design map-fresh --design map-aged --throughput-only map-fresh --throughput-only map-aged \
  --throughput-only-why 'T-DESIGN-1 needs only their throughput' \
  --input-mode ram --core 4 --title 'Book design {design} on debian, 12302019, the file in memory'
```

## Run the demo

`docs/` holds a static page that replays one symbol's extract on the same `FastBook` as the native build, compiled with `em++ -O3 -msimd128` into a fixed 1 GiB memory, and animates its depth and trades. The extract and the engine are made locally into `docs/local/`, which is gitignored, so no market data is committed. The page is not deployed anywhere. <!-- figures: not measured -->

```sh
cmake --preset release && cmake --build --preset release --target itch_extract
python3 scripts/demo.py extract --day data/12302019.NASDAQ_ITCH50 --symbol AAPL
python3 scripts/demo.py build      # needs EMSDK set
python3 scripts/demo.py serve      # then open http://127.0.0.1:8000/
```

The server sends the cross-origin isolation headers, so the browser's clock is clamped to 5 µs in Chrome rather than 100 µs, and `file://` cannot load the engine. The page shows messages/sec from whole batches only and no per-message latency, and says why. <!-- figures: not measured -->

## Check everything

```sh
scripts/check.sh               # every stage, one at a time
scripts/check.sh --quick       # the stages a change should pass before a commit
scripts/check.sh --list        # the stages
scripts/check.sh --only NAME   # one stage
```

It reads nothing from `data/`. Each stage's log is in `build/check-logs/`. Its readme stage runs `scripts/gate_numbers.py`, which holds every figure on this page, RESULTS.md, WRITEUP.md and docs/DETAILS.md to the results file its line cites, beside a word its sentence shares, and each verdict word to its target's result. It cannot tell when two figures of one sentence swap places, or when a figure is copied from another place in its file that shares a word: `in 9 of 10 runs` passes wherever 9 and 10 stand in one table of the file, and `3.04 billion` passes since the oracle file's bar of `3,037,078,470` messages rounds to it. It reads a verdict by its word, and as a negation only not, never, no, cannot or a word ending in n't between that word and the target it names, or none straight after that word, so a verdict said in other words, negated another way ("hardly", "far from", "by none of its runs"), or turned round further back in its sentence, passes. It reads no count written as a word ("ten") on a line that cites no results file, and it does not follow arithmetic, so a claim derived from figures, such as a rank, a share or a sum, is not checked. The demo stage opens the page in a headless browser: set `ITCH_BROWSER` to a Chrome or Chromium binary, or pass `--without-browser` to run the rest of that stage, and the summary says so.
