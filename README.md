# itch-orderbook

A parser and limit order book for Nasdaq ITCH 5.0 in C++23, built to be measured. Every target in [BENCHMARKS.md](BENCHMARKS.md) has a source, every figure here comes from a file in [results/](results/), and failures stay in the table.

## Where it stands

This is Phase 2 of the plan in [TASKS.md](TASKS.md): the harness, on a stub book.

Built:

- A parser for the framed feed, with no abort reachable from wire content.
- `FastBook`, a stub that does what the harness needs and is not the book this project is for, and a slow reference book to diff it against.
- An oracle that compares the two after every message of a real day, and trade-print checks against SEC MIDAS and Nasdaq CrossStats.
- A benchmark harness that records its host, refuses to publish a run it cannot stand behind, and reads hardware counters on Linux.
- Fuzz targets, sanitizer builds, and a fault matrix that shows each check failing on a planted bug.

Not built: the real book, SIMD, the backtester and the demo. So no result below is a result for the real book. The book in every row is the stub.

The GitHub Actions workflow in `.github/workflows/ci.yml` has never executed on GitHub, because this repo has no remote. [NOTES.md](NOTES.md) says which jobs were run by hand and how.

## Build and test

You need CMake, Ninja, Python 3 and a C++23 compiler, taken from `CC` and `CXX`. Clang and GCC 14 both build it.

```sh
cmake --preset release
cmake --build --preset release
ctest --preset release
```

The presets are `release`, `asan-ubsan`, `tsan`, `fuzz`, `tidy` and `wasm`. `wasm` needs `EMSDK` set. `fuzz` needs a Clang with libFuzzer.

Third-party code comes through CMake FetchContent, each pinned by SHA-256 in `cmake/ItchDependencies.cmake`, into `build/_downloads`. Two options are off by default:

```sh
cmake --preset release -DITCH_COMPARISON_QUEUES=ON       # the queues T-SPSC-1 compares against
cmake --preset release -DITCH_LIBURING_ROOT=<prefix>     # a liburing build, Linux only
```

## Fetch the data

The ITCH days and reference files are not in this repo. They go to `data/`, which is gitignored.

```sh
python3 scripts/fetch_data.py --day 12302019     # fetch one day and verify it
python3 scripts/fetch_data.py --ref all          # CrossStats and MIDAS
scripts/check_real_day.sh                        # the checks that need a real day
```

## Check everything

```sh
scripts/check.sh               # every stage, one at a time
scripts/check.sh --quick       # the stages a change should pass before a commit
scripts/check.sh --list        # the stages
scripts/check.sh --only NAME   # one stage
```

It reads nothing from `data/`. Each stage's log is in `build/check-logs/`.
